# 期限みまもり

商品の賞味期限を登録し、期限が近い順に確認できるシンプルなWebアプリです。

## 使い方

インストールや有料サービスの契約は不要です。

1. JANコードを数字で入力するか、「カメラで読む」で商品のバーコードを読み取ります。
2. 初回だけ商品名を入力します。同じJANコードは次回から以前の商品名が自動表示されます。
3. 賞味期限を入力し、「商品を登録」を押します（JANコードなしの登録も可能です）。
4. 確認した商品は「確認済みにする」、不要な商品は「削除」を押します。

データは使用中のブラウザー内（localStorage）に保存されます。同じ端末・同じブラウザーで開いてください。ブラウザーのデータを削除すると、登録内容も消えます。

## スマートフォンでカメラを試す

カメラはセキュリティ上、`https://` または端末自身の `localhost` で開いたページでのみ利用できます。スマートフォンへ公開するときは、静的サイトをHTTPSで配信できる無料ホスティング（GitHub Pagesなど）を利用してください。

1. HTTPSで公開したURLをiPhone版SafariまたはAndroid版Chromeで開きます。
2. 「カメラで読む」を押し、カメラの利用を「許可」します。
3. 商品のバーコード全体を緑色の枠へ入れます。読み取ると画面が閉じ、JANコードが入力されます。
4. 初回は商品名と賞味期限を入力して登録します。もう一度同じバーコードを読むと商品名が自動表示されることを確認します。
5. JAN-8（8桁）とJAN-13（13桁）の商品で試します。読み取れない場合は、レンズを拭き、明るい場所でバーコードを横向きにして、枠いっぱいに映してください。
6. カメラを許可しなかった場合や利用できない場合も、JAN欄へ8桁または13桁の数字を入力できます。

対応ブラウザーでは標準の `BarcodeDetector` を使い、非対応のiPhone Safariなどではアプリ内蔵のJANデコーダーへ自動で切り替わります。画像を外部へ送信せず端末内で処理するため、外部API・有料サービス・追加料金はありません。

### iPhone Safariでの確認手順

1. iPhoneの「設定」→「Safari」→「カメラ」が「確認」または「許可」になっていることを確認します。
2. Safariで **https:// で始まる公開URL** を開きます（通常のHTTP URLではカメラを使えません）。
3. 「カメラで読む」をタップし、初回の確認画面で「許可」を選びます。
4. JANバーコードを横向きに持ち、緑の枠をバーコードの左右の余白まで含むように合わせます。反射を避け、10〜20cmほど離してゆっくり動かします。
5. 読み取り画面が自動で閉じ、JANコード欄へ数字が入ったことを確認します。
6. 商品名と賞味期限を入力して登録し、同じJANをもう一度読むと商品名が自動入力されることを確認します。
7. 許可を誤って拒否した場合は、アドレスバー左のページ設定（`ぁあ`）→「Webサイトの設定」→「カメラ」→「許可」に変更して再読み込みします。

## 開発者向け

```bash
python3 -m http.server 8000
```

その後、ブラウザーで <http://localhost:8000> を開きます。

ロジックのテストは次のコマンドで実行できます。

```bash
node --test tests/app.test.js
```

## 商品を編集する

商品一覧の「編集」で、商品名・賞味期限・JANコードを変更できます。
「保存」でブラウザー内に保存し、「キャンセル」で変更を破棄します。
確認済み状態は維持されます。JANは登録時と同じJAN-8/JAN-13の検証を使い、空欄も許可します。
編集時はJANを入力しても商品名を自動で置き換えません。

商品名またはJANを変えると、新しいJANには編集後の商品名を記憶します。
旧JANを他の商品が使用していれば、その商品の名前を記憶します（複数なら登録順の最初）。
他の商品が使用していなければ旧JANの記憶を解除します。期限だけの変更では記憶を変更しません。
同じJANの別商品の表示名は変更しません。
保存エラー時は編集画面と入力内容が残ります。複数タブでの同時編集は避けてください。

### スマートフォンでの編集確認

変更版を開き、テスト用の商品で確認してください。公開済みURLはローカルの編集だけでは更新されません。

1. 商品を登録し「確認済み」にしてから「編集」を開きます。
2. 商品名・期限・JANを変えて「キャンセル」。元の表示が変わらないことを確認します。
3. 再び編集し、正しいJAN-8/JAN-13で保存。変更内容・期限順・確認済み状態を確認します。
4. ページを再読み込みして変更が残ることを確認します。
5. 登録欄に編集後のJANを入力し、新しい名前が表示されることを確認します。
6. 不正なJANや空の商品名では保存できず、JAN空欄は保存できることを確認します。
7. 登録・確認済み切替・削除と、HTTPS環境でのカメラ読取も確認します。

## iPhone向け読み取り改善版

Safariでは、表示中のカメラ映像の切り抜き（object-fit: cover）に合わせ、
緑枠とその周囲の中央領域を解析します。最大21位置×5方向（水平・約±5度・±9度）を
順に調べ、3行平均／1行と4種類のしきい値（局所的な明暗補正を含む）を試します。
解析幅は最大1280px、1回の処理は最大4走査・約18msを目安に分割します。
18msは処理間の判定値で、1走査が遅い端末では超える場合があります。

カメラは背面・1920×1080を希望値として要求し、対応端末だけ連続フォーカス等を試します。
実際の解像度・フォーカス可否は端末とSafariに依存します。AndroidなどのBarcodeDetector対応環境では
標準APIを優先し、検出APIが失敗した場合は独自解析へ切り替えます。
誤読を減らすため、別々に取り込んだ2フレームで同じJANが得られた場合に確定します。
画像は端末のメモリー内だけで処理し、外部送信・外部API・CDN・追加ライブラリを使用しません。

### 実機での確認

ローカルの変更だけではGitHub Pagesの公開版は更新されません。
改善版を配信したHTTPS環境で、テスト用商品を使って確認してください。

1. Safariで「カメラで読む」を開き、JANと左右の白い余白を緑枠へ入れます。
2. バーコードを横向きにし、ピントが合う距離で1〜2秒静止します。「候補を確認中」の後にJANが入力されるか確認します。
3. JAN-13とJAN-8をそれぞれ複数商品で試し、読み取った数字が印刷された数字と一致するか確認します。
4. 枠の上下・左右への少しのずれ、距離の変化、約5〜9度の傾きでも試します。
5. キャンセル後にカメラが停止し、再び開けることを確認します。手入力、登録、編集、確認済み切替も確認します。
6. Androidでは標準読み取りが継続して動くことを確認します。

機種・iOS版・商品・読めるまでの秒数を記録すると比較できます。
自動テストは合成画像と模擬カメラを使用します。実写での成功率・速度は未保証です。
強い反射、曲面、ピンぼけ、細すぎるバー、大きな傾き、古い端末では読み取りに失敗する可能性があります。
現段階では外部ライブラリを追加せず既存デコーダーを改善しています。
実機でなお不足する場合は、実写の再現条件を使ってクライアント内処理のライブラリと比較するのが次の対応です。
